  • ai_code_documentation.py Read more...

    An agentic AI documentation generator. Given a Git repo URL or a Zip upload, it analyzes the codebase and produces a structured, 14-section project documentation file (Markdown + PDF) without a developer writing it by hand. The system is a multi-agent pipeline orchestrated with LangGraph, not a single-shot prompt. An ingestion agent clones the source and builds the file tree, a code-understanding agent produces per-file summaries and detects database, ML and API signals, and a planner decides which sections apply and fans out drafting in parallel. Specialized writer agents draft each section from a retrieved code index rather than raw code, so repositories larger than one context window are handled. Every draft is checked by a verifier agent against real code facts, and failures loop back to the same writer within a retry budget. This guards against hallucinated install commands, fake API routes and invented database tables. A summary agent writes the Abstract and Table of Contents last, from verified content only. Exposed through a FastAPI service with background job queueing, status polling and PDF/Markdown download. LLM access goes through a provider registry supporting OpenAI, Groq and Gemini, and offline test suites run the full graph with the LLM stubbed. Tools & Technologies: Python, LangGraph, FastAPI, OpenAI, Groq, Gemini

  • agentic_rag_chatbot.py Read more...

    A multi-agent Retrieval-Augmented Generation chatbot where agents communicate through the Model Context Protocol (MCP), answering questions over multiple document formats (PDF, DOCX, PPTX, CSV, TXT, Markdown). Four agents split the work: an IngestionAgent parses and chunks documents, a RetrievalAgent generates embeddings and runs semantic search, an LLMResponseAgent builds the final prompt from the retrieved context, and a CoordinatorAgent orchestrates the flow. All agents exchange structured, traceable MCP messages (sender, receiver, type, trace_id, payload) through a message broker, with error propagation and recovery across agents. Supports four query types: answering with source citations, generating comprehension questions, summarizing documents, and evaluating user answers. Embeddings come from Google, vectors are stored in Pinecone, and responses are generated by Llama through Groq. Exposed through a FastAPI backend (upload, query, status and health endpoints) with a Streamlit chat UI that includes an interactive architecture viewer. Tools & Technologies: Python, FastAPI, Streamlit, LangChain, Pinecone, Groq (Llama), Google Embeddings, MCP

  • medmcqa_finetuning.ipynb Read more...

    An end-to-end pipeline for fine-tuning a lightweight causal language model (Qwen3-0.6B) on MedMCQA, a dataset of over 194k multiple-choice medical entrance exam questions, using the Hugging Face ecosystem on a single Tesla T4 GPU. Questions and answer options are formatted into text prompts and tokenized, using subsampled splits (2,000 train, 500 validation) to keep training fast. Supervised fine-tuning runs with the Hugging Face Trainer over 2 epochs, tuned for memory stability on limited hardware with a small batch size, gradient accumulation, gradient checkpointing, bf16 precision and expandable CUDA memory segments to avoid out-of-memory fragmentation. On the validation split, the base model scored 22.20% accuracy while the fine-tuned model reached 68.60%. The test split was unusable for automated evaluation because it ships without ground-truth labels. The trained model and tokenizer were saved, archived and pushed to the Hugging Face Hub. Tools & Technologies: Python, PyTorch, Hugging Face Transformers, Datasets, Trainer, Qwen3, bf16, Tesla T4
